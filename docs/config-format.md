# Формат конфигурации интерфейса

Файл, который конструктор сохраняет в разделе «Экспорт» и принимает в разделе «Импорт». Один и тот же формат используют веб-версия, мобильное приложение ([accessible-ui-constructor-mobile](https://github.com/TewCorejz/accessible-ui-constructor-mobile)) и — в будущем — банковское приложение, которое должно показать пользователю собранный им интерфейс.

- **Машинное описание:** [`schema/interface-config.schema.json`](../schema/interface-config.schema.json) (JSON Schema, draft 2020-12).
- **Примеры:** [`docs/examples/`](examples) — настоящие файлы, выгруженные из конструктора.
- **Текущая версия формата:** `1`.

## Поля

| Поле | Тип | Обязательно | Описание |
|---|---|---|---|
| `formatVersion` | число | да | Версия формата. Сейчас `1`. |
| `$schema` | строка | нет | Ссылка на схему — для редакторов и валидаторов. |
| `name` | строка, 1–80 символов | да | Название интерфейса, которое видит пользователь. |
| `theme` | строка | да | Шаблон, см. таблицу ниже. |
| `appearance` | объект | нет | Оформление. Если нет — используются настройки шаблона. |
| `widgets` | массив, до 30 | да | Виджеты в порядке отображения. |

### `theme` — шаблон

| Значение | Шаблон | Для кого |
|---|---|---|
| `default` | Обычный | — |
| `senior` | Крупный текст | Пожилые люди |
| `focus` | Фокус | Люди с когнитивными особенностями |
| `contrast` | Высокий контраст | Люди со слабым зрением |
| `student` | Студент | Студенты |

### `appearance` — оформление

| Поле | Тип | Описание |
|---|---|---|
| `fontSize` | целое 12–28 | Размер основного текста в пикселях. `14` — обычный. Элементы масштабируются вместе с текстом. |
| `primary` | `#RRGGBB` или `null` | Основной цвет: кнопки, иконки, акценты. `null` — цвет шаблона. |
| `secondary` | `#RRGGBB` или `null` | Дополнительный цвет: фон виджетов. `null` — цвет шаблона. |

Цвет текста на фоне `secondary` приложение подбирает само (чёрный или белый — что контрастнее). Банковскому приложению рекомендуется делать так же и предупреждать пользователя, если контраст `primary` и `secondary` ниже 3:1 (WCAG 2.2, критерий 1.4.11).

### `widgets[]` — виджет

| Поле | Тип | Обязательно | Описание |
|---|---|---|---|
| `id` | строка | да | Идентификатор внутри интерфейса. |
| `type` | строка | да | Тип виджета, см. ниже. |
| `wide` | `true` / `false` | да | Во всю ширину или в половину (на компьютере и планшете; на телефоне все виджеты во всю ширину). |
| `column` | `1` / `2` | нет | Колонка узкого виджета: `1` — левая, `2` — правая. Без неё виджет встаёт на следующее свободное место. |

| `type` | Виджет |
|---|---|
| `balance` | Баланс |
| `qr` | Оплата по QR-коду |
| `history` | История переводов |
| `quick` | Быстрая оплата |
| `studentQr` | Мои QR-коды (студент) |
| `subscriptions` | Подписки (студент) |
| `mobile` | Мобильная связь (студент) |

## Пример (JSON)

```json
{
  "$schema": "https://raw.githubusercontent.com/TewCorejz/accessible-ui-constructor/main/schema/interface-config.schema.json",
  "formatVersion": 1,
  "name": "Мой удобный банк",
  "theme": "default",
  "appearance": { "fontSize": 14, "primary": "#1f5fbf", "secondary": null },
  "widgets": [
    { "id": "balance-1", "type": "balance", "wide": false },
    { "id": "qr-1", "type": "qr", "wide": false, "column": 1 },
    { "id": "history-1", "type": "history", "wide": true }
  ]
}
```

Тот же интерфейс в [YAML](examples/interface.yaml) и [XML](examples/interface.xml). В XML версия и поля передаются так:

```xml
<interface formatVersion="1">
  <name>Мой удобный банк</name>
  <theme>default</theme>
  <appearance fontSize="14" primary="#1f5fbf" />
  <widgets>
    <widget id="qr-1" type="qr" wide="false" column="1" />
  </widgets>
</interface>
```

## Правила совместимости

- Файлы без `formatVersion` (созданные до её появления) читаются как версия `1`.
- Файл с версией **больше** поддерживаемой не открывается: пользователь видит «Файл создан более новой версией конструктора».
- Новые **необязательные** поля добавляются без смены версии; старые приложения их игнорируют при чтении.
- Удаление или переименование полей, смена смысла значений — только с увеличением `formatVersion`.

## Проверка

```bash
pnpm check:schema
```

Проверяет примеры из `docs/examples/` по схеме; то же выполняется в CI. Для своих файлов можно использовать любой валидатор JSON Schema 2020-12, например [ajv](https://ajv.js.org/).
