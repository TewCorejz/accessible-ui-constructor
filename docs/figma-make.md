# Работа с Figma Make

Исходный прототип живёт в [Figma Make](https://www.figma.com/make/FzdRdXWTrVs7QtX0a9d9p8/). Этот репозиторий — его код, выгруженный для дальнейшей разработки.

## Как обновить код из Figma Make

1. Откройте прототип в Figma Make → вкладка **Files**.
2. Скачайте код (меню **⋯** → **Download**) и распакуйте архив.
3. Создайте ветку: `git switch -c sync/figma-make-YYYY-MM-DD`.
4. Скопируйте содержимое архива поверх репозитория, **не трогая** `README.md`, `docs/`, `.github/` и другие файлы, которых нет в архиве:

   ```bash
   rsync -av --exclude .DS_Store --exclude README.md "/путь/к/архиву/" ./
   ```

5. Посмотрите изменения (`git diff`), проверьте сборку (`pnpm install && pnpm build`) и откройте pull request.

## Служебные файлы

| Файл / папка | Зачем нужен |
|---|---|
| `.figma/` | Скрипты и настройки Figma Make (установка, запуск, деплой, `site.json` с мета-описанием). Нужны, чтобы репозиторий можно было снова импортировать в Figma Make. |
| `AGENTS.md`, `CLAUDE.md` | Инструкции для AI-агента внутри Figma Make. |
| `.mise.toml` | Версии Node.js и pnpm, которые использует Figma Make. |
| `vite.config.ts` | Содержит плагины Figma Make; в обычной сборке они безопасны. |

## Git LFS

Figma Make по умолчанию кладёт в проект `.gitattributes`, который отправляет картинки в Git LFS. Для небольшого прототипа это не нужно, поэтому в репозитории используется обычный `.gitattributes`. Если в проекте появятся тяжёлые медиафайлы — можно вернуть LFS.
